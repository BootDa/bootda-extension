# 단계별 개발 계획

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| 0 | React/TS/Vite 초기 구조, 공통 타입, 문서 | 빌드 결과를 개발자 모드에서 로드해 팝업 확인 |
| 1 | 사람인 상세 파서와 페이지 UI | 익명화된 HTML fixture 및 실제 상세 공고에서 정보 추출, 마감일 미확인/SPA 이동 처리 |
| 2 | 잡플래닛 기업 확인 | 사용자 선택, 동명 기업, 미확인 값, 탭 복귀/종료, 접근 제한 fallback 검증 |
| 3 | LLM 기술스택 추출 | 명시적 기술만 추출, 중복 제거, 스키마/비용 제한, 실패 시 수동 입력 |
| 4 | Google Identity/Sheets | 최소 권한 승인, 신규 파일 자동 생성, 헤더/상태 설정, 동일 계정 재사용, 중복 및 재시도 검증 |
| 5 | 전체 흐름 통합 | 실제 사람인→잡플래닛→기술스택→시트 저장 E2E |
| 6 | 출시 준비 | 권한/개인정보처리방침, OAuth 검증 필요 여부, Chrome Web Store 심사, 릴리스 자동화 검토 |

각 단계는 독립 PR로 진행한다. 테스트 fixture에는 계정 정보, 쿠키, 지원서 등 개인정보를 포함하지 않는다. 기존 웹앱 지원이력과 신규 지원예정목록을 연결하는 기능은 MVP 이후 검토한다.

테스트: 파서 단위 테스트, 메시지/세션 전이 테스트, Google API 및 LLM 모의 응답, 권한 거절/401/403/429/타임아웃, 중복/계정 전환, 실제 브라우저 통합 테스트. 실제 외부 서비스 테스트 결과와 모의 테스트를 분리하여 보고한다.
